# POSIX profile research

Status: research draft, 8 September 2026. No backend conformance tests have run. This is a starting ledger, not a completed conformance claim or an approved API.

The [design proposal](../design/VirtualFileSystem-design.md) selects POSIX.1-2024, Issue 8, for a bounded filesystem subset. Each supported public operation still needs a mapping to applicable clauses, chosen alternatives, errors, limits, and executable evidence.

## How to read the evidence

- **I8-direct** means the relevant normative sections were read from official Issue 8 HTML retrieved directly. It verifies the stated rule, not every clause on the page.
- **I8** means the relevant Issue 8 normative text was recovered from the search index of the primary Open Group page. Direct page retrieval did not succeed. It is evidence for the listed rule, not proof that the entire page was audited.
- **Earlier** means a primary source from Issue 7 corroborates the rule, but Issue 8 verification remains open.
- **Design** means the repository proposal commits to the behavior. This does not establish its exact POSIX requirements.
- **Open** means neither a complete clause audit nor a policy decision exists.

All test descriptions below are proposed tests. None is a passing result. Stable IDs can be used in test names and future decisions; preserve them when splitting rows.

## Applicability

The profile covers regular files, directories, symlinks, hard links, and handles within one volume. Caller credentials replace relevant process identity inputs; Effect manages execution and lifetime. The API need not reproduce C argument shapes or integer descriptor allocation.

The design excludes special files, process execution, signals, memory mapping, descriptor duplication, advisory locks, restricted roots, and durable commits. POSIX clauses for those facilities do not become backend requirements merely because they appear on an otherwise applicable page. Snapshot semantics are project requirements, outside POSIX.

The proposed operation families are lookup and directory-relative lookup; open/close; read/write and positional I/O; seek/truncate; stat/lstat/fstat; mkdir/rmdir; link/unlink; symlink/readlink; rename; permission/ownership/time changes; and directory enumeration. Final names and flags remain open.

| POSIX-H09 | I8-direct, [ftruncate DESCRIPTION](https://pubs.opengroup.org/onlinepubs/9799919799/functions/ftruncate.html)                                  | Shrink preserves the offset; extension reads as zeroes. | POSIX-H10 | I8-direct, write DESCRIPTION and ERRORS; project policy partly open                                                                            | Capacity crossing writes the prefix that fits. H06 is a real Issue 8 scope decision. Deferring sparse storage does not require deferring these seek modes. A simple dense-file implementation is an option; otherwise list their exclusion explicitly.

The Effect adapter intentionally differs on append read cursors and shrink clamping. Backend tests must assert H07/H09 independently of adapter compatibility tests.

Do not derive a universal error-precedence order from one host. The final ledger must distinguish mandatory failures, permitted failures, and project choices when causes overlap. JS invalid numbers and foreign handles need defined validation even where the C interface has undefined behavior.

## Decisions needed before implementation contracts

| ID        | Decision                    | Recommendation for discussion                                                                                                                                                                                                |
| --------- | --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POSIX-D01 | Exact operation/flag set    | Publish a whitelist. Decide H06 and directory search handles explicitly. Reject unsupported combinations rather than ignoring them.                                                                                          |
| POSIX-D02 | Credentials and privilege   | Explicit privilege is accepted. Keep caller state immutable; specify the exact permission bypass and metadata-change rules.                                                                                                  |
| POSIX-D03 | Path limits                 | Publish byte units, maximum component/path length, symlink traversal count, and expansion accounting. Confirm Issue 8 minima before choosing numeric defaults.                                                               |
| POSIX-D04 | Numeric I/O range           | Choose integer offset representation, maximum file size, and transfer bounds together. No implicit rounding or host-dependent defaults.                                                                                      |
| POSIX-D05 | Partial I/O                 | Issue 8 verification is complete for capacity crossing. Review the [quota transfer algorithm](posix-io-contract.md) and finalize numeric limits, cancellation, and gap accounting. Unlinked-open byte retention is accepted. |
| POSIX-D06 | Permission policy           | Set sticky-directory option, group inheritance, special bits, metadata mutation privileges, and access-check timing.                                                                                                         |
| POSIX-D07 | Directory identity/lifetime | Decide removal while used as cwd or directory handle; ensure rename identity does not depend on remembered path strings.                                                                                                     |
| POSIX-D08 | Timestamps                  | Choose precision, clock input, immediate versus deferred updates, and rename-file ctime policy. Snapshot preservation follows the chosen metadata model.                                                                     |

## Source gaps and follow-up

On the first pass on 8 September 2026, web-tool Open Group requests for `open`, XBD chapter 4, and `lseek` returned HTTP 403. Requests for `write`, `ftruncate`, `rename`, and `unlink` also failed. Indexed primary-source text recovered the I8 clauses above. Search results repeatedly substituted older editions for other pages; those results were not upgraded to Issue 8 evidence.

A later direct `curl` retrieval on the same date succeeded with HTTP 200 for `write`, `ftruncate`, `close`, `lseek`, `open`, and XSH chapter 2. H05-H11 now use directly read normative text; the [I/O contract proposal](posix-io-contract.md) records narrowed recommendations. Earlier access failures are historical, not a current universal source blocker.

The next standards pass should obtain readable Issue 8 normative text for the Open/Earlier rows, then audit DESCRIPTION, ERRORS, and relevant option shading for every selected operation. A subsequent direct pass verified selected mkdir, chmod, chown, utimensat, access, and timestamp clauses in the [permission and metadata proposal](permissions-and-metadata.md). Complete namespace/error and variant audits remain open. Do not treat change-history snippets or informative rationale as replacement requirements.

XSH 2.9.7 descriptor-operation atomicity and XSH 2.3 error rules were read directly for the I/O proposal. Selected file-access and timestamp requirements are now verified; their full per-operation applicability and [limits.h](https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/limits.h.html) still need an audit.

For each final operation, add a test reference and result record only after execution. A local POSIX host can supply comparison evidence, but its implementation choices and defects are not the standard. Historical exploratory pass counts do not close any row in this ledger.
