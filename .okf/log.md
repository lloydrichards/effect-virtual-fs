- **Reference keys (#201)**: Core gains a public `ReferenceKey` schema of the volume identity, an epoch and a tag, 16 bytes each carried as base64, and the inode number as a decimal string; the tag is HMAC-SHA-256 over the other three under a per-volume secret drawn from `globalThis.crypto.getRandomValues` rather than a seedable `Random`, computed in core without `Crypto`, so a key cannot be forged from another, with `volume.referenceKey` and `volume.resolveReferenceKey` as coordinated reads on the volume rather than the caller, since inode numbers are guessable and a caller-level resolve would skip search permission. Every construction draws a new epoch after its incarnation, overlays included, and only a live reopen resumes the epoch and secret the live image's runtime block now stores, so a key survives a restart and never resolves in a restore, fixture or overlay under the same identity. Another identity or epoch fails `ForeignReference`, a gone object `StaleReference`, a malformed key or forged tag `InvalidReference`. NFS filehandles become version 2, `version | identity | epoch | ino | tag` in 57 bytes, so a client cannot reach an object below a directory it may not search by editing an inode number; the registry, its serial, the full-registry sweep, the PUTFH `stat` probe and `NfsServerLimits.maxFilehandles` go. Over a volume surviving at least a process crash `fh_expire_type` is `FH4_PERSISTENT`, handles resolve after a restart and a foreign handle is `STALE`; memory volumes send `FH4_VOLATILE_ANY | FH4_NOEXPIRE_WITH_OPEN` and answer `FHEXPIRED` after a restart. PUTFH on a busy volume answers `DELAY`, any other code within PUTFH's RFC 8881 error list or `SERVERFAULT`, and GETFH on a removed object answers `STALE` instead of returning its old handle; the export takes its capacity from its volume. Two opens of one live image share its keys, which is documented rather than detected. Stored live images must be regenerated. A new decision file records the decisions; the object references contract, the snapshot-local identity, rebuild, durability, reference-mutation, NFS profile ladder, error mapping and writable scope decisions, both NFS profiles and the three NFS ledgers are updated.

Every line is checked as it ends against the node rules and one budget meter, the budget gaining `lineBytes` and `DecodeLimits` an optional `maxLineBytes` that defaults to `maxEncodedBytes`, so the hostile-input promise is now rejection before more than one line is allocated, and a line is refused at the byte where it first crosses its own bound or the input's, so the field named does not depend on chunking; the rules spanning nodes run after the last line. `encodeSnapshotStream` and `decodeSnapshotSink` join `encodeSnapshot` and `decodeSnapshot`, and `encodeSnapshot(snapshot, limits)` runs the same meter, which lets `CheckpointStore.save` encode under its limits and decode nothing. The strict decoding, JSON snapshot and rebuild decisions and the snapshots, checkpoint and tree transfer contracts are updated.

- **One tree schema, Draft B: Merkle identity, change-event deltas and one budget (#185)**: A snapshot's identity is now a Merkle tree: each node's digest covers its kind, uid, gid, mode, timestamps and payload, a directory's also covers its entries' names and child digests in name-byte order, and the identity covers the root's digest and the hard-link groups as sorted path lists, so a hard link is hashed once and trees differing only in which names share a node differ. It keeps the name `effect-vfs-semantic-sha256-v1`, both goldens are regenerated, and the delta contract records this as the one bump made without a new identifier, inside the 0.6.0 major. A delta is `{ format: "effect-vfs-delta", version: 1, base, target, changes }` in the existing `Added | Removed | Updated` vocabulary, each change carrying only the node it leaves, with a payload only where it changes and a link to the group's first path for a joining hard link; the `WireDocument` and `WireStoredMetadata` twins go, and no source file says `trusted` any more. Diffing skips subtrees whose digests agree, and applying and inspecting fold the changes over the base value, check each against the base (a change it does not bear out fails at `changes.<index>`, and only a missed target identity at `changes`), hold the target to `maxTargetRecords` and `maxEntries` as a diff does, and digest only what they rewrote to check the target. - **Recursive tree operations (#205)**: `Caller` gains `walk(directory, options?)`, a `Stream` of `WalkEntry` (path relative to the root, name, reference, listing directory, kind, depth), pre-order by default or post-order, each directory's names in byte order; every directory is one observation under one permit, the children's kinds come from the same read, and nothing is written, so a walk holds no handle and refreshes no access time. Each directory below the root is reached by name, with search permission on every directory above it, so a directory that vanished or was renamed out after its listing is skipped. Links are reported, never followed, and optional `maxDepth`, `maxEntries` and `maxBytes` fail `LimitExceeded` after the earlier entries are handed on, a post-order walk judging depth before it reads a directory. `mkdir(path, { recursive: true })` creates the missing directories inside one transition through `lookup`, walking dots, following links on the way, creating only names the caller wrote, so a failure creates nothing, and reports the change to the parent of the directory the path ends on. `remove(entry, { recursive, force })` empties a directory over a post-order walk, one change per entry removed by name, so a subtree renamed out of the target is left alone, stops at the first failure naming the entry, refuses an unreadable directory with entries without changing permissions, and forgives only the target itself going missing; a trailing slash on a path to a file now fails `NotDirectory`. Memory's recursive `makeDirectory`, `readDirectory`, `glob` and `remove` run on the core verbs, which fixes `force` reporting success over a partial tree, and `TreeTransfer.fromCaller` reaches entries by path instead of holding every directory handle; recursive listings no longer refresh directory access times. A new decision file records the decisions, and the mutation and observation, memory adapter and tree transfer contracts are amended.

- **Atomic setattr (#209)**: `Caller` gains `setattr(target, { size?, mode?, owner?, times?, expected? })`, one change with one draft, one revision, one clock reading and one `Update`. Its checks run in a fixed order, first failure winning: every attribute validates before the target resolves and names itself in `field` (non-object attributes fail typed too), then the lookup, then a size on a non-file, then ownership (`NotPermitted`) for mode, owner and explicit times, then write permission (`AccessDenied`) for size and both-now times, then the size limits. It applies size, owner, mode, times, the POSIX composition of chown then chmod, so a requested mode keeps the setuid and setgid bits that an owner change would clear; the published `SetattrOptions` schema bounds the size as the verb does. An empty `setattr` checks and changes nothing, as Linux `notify_change` does. `chmod`, `chown`, `utimes` and `truncate` are one-field calls of the same body; `truncate` now rejects a negative length before the lookup. NFS SETATTR makes one `setattr` call and its `attrsset` is all or nothing; before the call it clears setuid, and setgid with group execute, from a mode sent with an owner change on a non-directory, as Linux knfsd `nfsd_sanitize_attrs` does, so `04755` with a new owner still ends at `0755`; an owner or group equal to the current one is dropped first as no change, as knfsd's `chown_ok`, `chgrp_ok` and `nfsd_sanitize_attrs` treat it, so an owner may re-send a group it is not a member of and an unchanged owner clears no set-ID bit, while core keeps POSIX chown and still refuses that group. That observation's revision goes to core as `expected: { revision }`, checked inside the change and failing `StaleReference` naming `expected` when another change landed first, so a racing chown can no longer leave setuid behind; SETATTR re-observes up to three times, then answers `DELAY`. The unscoped open is declined: NFS forks each open's scope from its handler scope instead of making and closing its own, and an export test pins that a closed open leaves no finalizer in that scope. Every check-order step has a setattr row in the operation-family table, and a truncate row joins it. A new decision file records the decisions, and the permissions and revisions contracts, the reference-mutations and public API decisions, the writable export scope and the NFS operations ledger are updated.
