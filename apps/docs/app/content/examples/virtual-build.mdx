# Build and save a browser filesystem

Select **Build and run** to see `Reading: 20` under **Console output**. All three callers can run the public sensor example. As **Editor**, change `20` to `21` in `src/value.js` and build again. The output changes to `Reading: 21`.

## Try the private calibration

1. As **Editor**, open `main.js` and uncomment `import "./secret.js"`. Select **Build and run**. The bundler now needs the private calibration module, so the read fails with `AccessDenied`.
2. Switch to **Reader** and build the same files. Reader can read the public sensor value but cannot read the calibration module either.
3. Switch to **Admin** and build again. The import runs `secret.js`, which adds its private offset to the sensor reading and logs the result. With the starter reading, you see `Secret: 42 (20 + 22)` followed by `Reading: 20`. Change the reading to `21` and run again to see `Secret: 43 (21 + 22)`.
4. As **Admin**, open `secret.js` and set **File access** to **Everyone can read**. Keep the import enabled. The diagram now shows mode `0644` and read-only access for Editor and Reader.
5. Switch to **Reader**. The lock disappears from `secret.js`. Open the file and select **Build and run**. Reader can inspect the calibration and run it, but only Admin can edit it.
6. To restrict the file again, switch to **Admin** and set **File access** to **Private**. The mode returns to `0600`. **Save checkpoint** keeps the current permissions with the files.

Admin can change **File access** on any regular file. **Private** keeps read and write access for the owner and Admin. **Everyone can read** also grants read access to other callers. Changing access preserves ownership.

## Follow the bytes

<CheckpointDiagram />

**Save checkpoint** snapshots the working files into a SQLite row. IndexedDB keeps the database in this browser profile. Each save replaces the previous checkpoint. Your source files and build output stay on your device.

1. **Inspect saved row** shows the snapshot’s timestamp and byte count. To find the database in developer tools, open **Storage** or **Application** → **IndexedDB** → **effect-vfs-checkpoints** → **entries**. The `workspace.sqlite` key holds the database bytes.
2. Reload to start with the original files. Choose **Reopen saved** to replace the working copy with your saved files.
3. Choose **Delete checkpoint** to remove the saved database and keep editing the files in memory.

## How the checkpoint reaches IndexedDB

**Save checkpoint** runs an Effect Atom command. After writing the current edit to the virtual file, the command encodes the volume and saves the snapshot:

```ts
yield* saveCheckpoint(yield* volume.snapshot())
```

The save effect binds the snapshot bytes to an Effect SQL query. The browser SQLite driver exports the database, then the effect waits for the IndexedDB write to finish.

```ts
yield* sql`INSERT INTO checkpoint VALUES (strftime('%Y-%m-%dT%H:%M:%fZ', 'now'), ${image})`
const store = yield* KeyValueStore
yield* store.set("workspace.sqlite", yield* sql.export)
```

The effect scope closes the database on success or failure. After a successful save or delete, the command refreshes the checkpoint atom. Its value controls **Reopen saved** and **Inspect saved row**.

For a server-side example, see [Save and restore SQLite checkpoints](/guides/sqlite-checkpoints).
