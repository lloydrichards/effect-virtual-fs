# Build and save a browser filesystem

Change `20` to `21` in `src/value.js`, then select **Run build**. The bundle exports `43`: `main.js` imports your value and adds `22`.

<FilesystemPlayground />

Select a file or folder by name, then use the **Files** toolbar to rename or delete it. Renaming a folder moves its contents. Deleting a folder removes every file and subfolder inside it. Enter paths from the volume root, such as `src/lib`. If you rename an imported module, update its import before building. Tree changes stay in memory until you save a checkpoint.

## Try another caller

Switch **Caller** to **Reader** and run the build again. Both callers see the same volume. File permissions determine what each identity can do.

## Follow the bytes

<CheckpointDiagram />

**Save checkpoint** snapshots the working files into a SQLite row. IndexedDB keeps the database in this browser profile. Each save replaces the previous checkpoint. Your source files and build output stay on your device.

1. **Inspect saved row** shows the snapshot’s timestamp and byte count. To find the database in developer tools, open **Storage** or **Application** → **IndexedDB** → **effect-vfs-playground** → **databases**.
2. Reload to start with the original files. Choose **Reopen saved** to replace the working copy with your saved files.
3. Choose **Delete checkpoint** to remove the saved database and keep editing the files in memory.

## How the checkpoint reaches IndexedDB

**Save checkpoint** runs an Effect Atom command. After writing the current edit to the virtual file, the command encodes the volume and saves the snapshot:

```ts
yield* saveCheckpoint(yield* volume.snapshot())
```

The save effect binds the snapshot bytes to an Effect SQL query. The browser SQLite driver exports the database, then the effect waits for the IndexedDB write to finish.

```ts
yield* sql`INSERT INTO checkpoint VALUES (strftime('%Y-%m-%dT%H:%M:%fZ', 'now'), ${image})`
const bytes = yield* sql.export
```

The effect scope closes the database on success or failure. After a successful save or delete, the command refreshes the checkpoint atom. Its value controls **Reopen saved** and **Inspect saved row**.

For a server-side example, see [Save and restore SQLite checkpoints](/guides/sqlite-checkpoints).
