# Build and save a browser filesystem

Open `/main.js` to see how it imports `value` from `./value.js`. Change `20` to `21` in `/value.js` and choose **Run build**. The browser bundles the two virtual modules and shows the generated JavaScript and the paths it read. You can add another file and import it by its relative path.

## What survives a reload?

1. Give `/value.js` a value you will recognize. Choose **Save checkpoint**, then **Inspect saved row**. The timestamp and byte count come from a query against your saved SQLite database.
2. Change the value again and run another build. Inspect the row again. Its timestamp stays the same because building only uses the working copy.
3. Reload this page. The editor starts with the two original files. Choose **Reopen saved** to replace the working copy with your checkpoint. Open `/value.js` to verify the value you saved. Any files you added before saving come back too.

## Where the bytes go

The editor and bundler share an in-memory Effect VFS volume. Switching files, saving, or building writes the current editor buffer into that volume. The build starts at `/main.js`; esbuild runs as WebAssembly in your browser and reads each imported module through the volume’s caller.

**Save checkpoint** captures the whole volume with `volume.snapshot` and encodes it with `Vfs.encodeSnapshot`. SQLite stores those bytes in the `image` column of a single row in the `checkpoint` table. The browser stores the resulting SQLite database as a byte array in IndexedDB. Each save replaces the previous database for this site and browser profile.

To inspect it yourself, open your browser’s developer tools and look under **Application** (or **Storage**) → **IndexedDB** → **effect-vfs-playground** → **databases** → **workspace.sqlite**. Clearing this site’s browser storage removes the checkpoint. **Reopen saved** reads the database, decodes the snapshot, and opens a fresh writable volume. It discards any unsaved edits in the current tab.

For the local Vite version, run `bun run --cwd apps/virtual-build demo` from a built repository checkout. For server-side persistence, see [Save and restore SQLite checkpoints](/guides/sqlite-checkpoints).
