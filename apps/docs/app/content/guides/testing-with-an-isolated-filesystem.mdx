# Test with an isolated filesystem

Use `@effect/vitest` with `MemoryFileSystem.layer` when each test should receive disposable filesystem state without
reading or writing the host disk.

## Install the test dependencies

Install the core volume, memory adapter, and matching Effect test integration with Vitest 5:

```sh
npm install @effect-vfs/core@latest @effect-vfs/memory@latest
npm install --save-dev "@effect/vitest@$(npm view @effect-vfs/memory peerDependencies.effect)" "@effect/platform-bun@$(npm view @effect-vfs/memory peerDependencies.effect)" vitest@^5.0.0
```

## Keep production code independent of storage

Write production code against Effect's `FileSystem.FileSystem` service:

```ts
import { Effect, FileSystem } from "effect"

export const writeManifest = (version: string) =>
  Effect.gen(function* () {
    const fs = yield* FileSystem.FileSystem

    yield* fs.makeDirectory("/dist", { recursive: true })
    yield* fs.writeFileString(
      "/dist/manifest.json",
      JSON.stringify({ version })
    )

    return yield* fs.readFileString("/dist/manifest.json")
  })
```

The program requests a filesystem but does not choose its implementation. Production can provide a host filesystem;
tests can provide a new in-memory volume.

## Provide fresh state to each test

Import the test API from `@effect/vitest` and return an Effect from `it.effect`:

```ts
import * as BunCrypto from "@effect/platform-bun/BunCrypto"
import { MemoryFileSystem } from "@effect-vfs/memory"
import { assert, describe, it } from "@effect/vitest"
import { Effect, FileSystem } from "effect"
import { writeManifest } from "./writeManifest.js"

describe("writeManifest", () => {
  it.effect(
    "should write the requested version when the filesystem is empty",
    () =>
      Effect.gen(function* () {
        const result = yield* writeManifest("1.2.3")

        assert.deepStrictEqual(JSON.parse(result), { version: "1.2.3" })
      }).pipe(Effect.provide(MemoryFileSystem.layer), Effect.provide(BunCrypto.layer))
  )

  it.effect(
    "should start without files from another test when a fresh layer is provided",
    () =>
      Effect.gen(function* () {
        const fs = yield* FileSystem.FileSystem

        assert.isFalse(yield* fs.exists("/dist/manifest.json"))
      }).pipe(Effect.provide(MemoryFileSystem.layer), Effect.provide(BunCrypto.layer))
  )
})
```

Each `it.effect` execution above materializes its own layer graph and volume. Files written by the first test are absent
from the second.

Do not call `Effect.runPromise` or `Effect.runSync` inside an Effect test. `it.effect` runs the returned Effect, supplies
Effect's test services, and keeps a scope open for the test.

## Seed a test layer from a fixture

`MemoryFileSystem.layerFromFixture` builds a core fixture volume and binds it to Effect's filesystem service:

```ts
import * as BunCrypto from "@effect/platform-bun/BunCrypto"
import { MemoryFileSystem } from "@effect-vfs/memory"
import { assert, it } from "@effect/vitest"
import { Effect, FileSystem, Layer, Path } from "effect"

const seededFileSystem = MemoryFileSystem.layerFromFixture({
  entries: [
    { kind: "directory", path: "/project" },
    {
      kind: "file",
      path: "/project/package.json",
      bytes: new TextEncoder().encode('{"name":"example","version":"1.2.3"}')
    }
  ]
})
const services = Layer.merge(seededFileSystem, Path.layer)

it.effect("should read the seeded package version", () =>
  Effect.gen(function* () {
    const fs = yield* FileSystem.FileSystem
    const path = yield* Path.Path
    const manifest = JSON.parse(yield* fs.readFileString(path.join("/project", "package.json")))
    assert.strictEqual(manifest.version, "1.2.3")
  }).pipe(Effect.provide(services), Effect.provide(BunCrypto.layer))
)
```

Provide a matching platform Crypto layer, as above, or your deterministic `Crypto.Crypto` implementation at the test
boundary. `Path.layer` provides POSIX paths in Effect 4. Omit the merge when the program does not need `Path`.

Separate builds of the same layer get separate volumes. Actions and assertions inside one build observe the same
writes. Reusing one layer value in a layer graph shares the volume through memoization; use `Layer.fresh` when a part
of that graph needs independent state.

The second argument accepts `Vfs.VolumeOptions`, including volume limits. The third accepts `Vfs.RootCallerOptions`,
including credentials and umask. Pass `undefined` as the second argument when only caller options are needed.
Invalid fixtures and options remain typed `VfsError` construction failures.

The layer adds no entries to the fixture. Include `{ kind: "directory", path: "/tmp" }` when temporary-file operations
need the default temporary directory. `MemoryFileSystem.layer` still creates `/tmp` for its empty filesystem.
Use `Vfs.fromFixture` and `MemoryFileSystem.bind` directly when adapter code and core callers need the same volume.

## Test against a core volume directly

When the code under test takes the `Volume` or `Caller` services, provide `Testing.layer` from
`@effect-vfs/core/Testing`. It builds a fresh volume, from a fixture when one is given, and a root caller on it.
`callerAs` makes a caller with other credentials on the same volume, and `collectChanges` collects watch changes
committed after the stream opened:

```ts
import * as BunCrypto from "@effect/platform-bun/BunCrypto"
import { VirtualFileSystem as Vfs } from "@effect-vfs/core"
import * as Testing from "@effect-vfs/core/Testing"
import { assert, it } from "@effect/vitest"
import { Effect } from "effect"

it.effect("should report the directory a guest cannot read when it is private", () =>
  Effect.gen(function* () {
    const volume = yield* Vfs.Volume
    const changes = yield* Testing.collectChanges(yield* volume.watch(), 1)

    yield* (yield* Vfs.Caller).mkdir("/private", { mode: 0o700 })

    const guest = yield* Testing.callerAs({ uid: 1000, gid: 1000, groups: [], privileged: false })
    const error = yield* Effect.flip(guest.readDirectory("/private"))

    assert.strictEqual(error.code, "AccessDenied")
    assert.deepStrictEqual((yield* changes).map((change) => change._tag), ["Create"])
  }).pipe(Effect.provide(Testing.layer()), Effect.provide(BunCrypto.layer))
)
```

`it.layer` from `@effect/vitest` builds its layer once for the whole `describe` block, so its tests share one volume.
Provide `Testing.layer()` to each test that needs state of its own.

## Write behavior-focused tests

Keep each test centered on one observable promise:

- Name it `should <observable outcome> when <relevant condition>`.
- Assert returned values, public errors, emitted events, or filesystem state rather than implementation details.
- Keep several assertions together only when they prove the same behavior.
- Use `assert` from `@effect/vitest` for ordinary equality and narrowing checks.
- Use Effect test services such as `TestClock` for time-dependent behavior instead of real sleeps.
- Use `Deferred`, `Queue`, or another deterministic signal for concurrent tests instead of polling.

## Let the test scope release resources

`it.effect` already provides a scope. Open files, temporary resources, derived streams, and watch subscriptions can use
that scope directly. You do not need to add `Effect.scoped` around the test body.

Explicit cleanup still belongs in the test when cleanup itself is the behavior being asserted. Otherwise, let the test
scope release resources when the returned Effect completes.

## Keep host access outside the assumption

The memory adapter replaces Effect's `FileSystem` service. It cannot intercept code that directly uses:

- `node:fs`;
- child processes;
- native extensions; or
- another API that accesses the host filesystem independently.

A test is isolated only when the code under test obtains filesystem access through the provided Effect service.

For the adapter constructors and layer types, see the
[`MemoryFileSystem` API reference](/api/memory/memory-file-system).

Use [an overlay workspace](/guides/overlay-filesystems) instead when a test or preview must start from an immutable
snapshot and report its final changes.
